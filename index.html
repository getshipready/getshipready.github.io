The gap after "it works"

AI builders get you to a demo. Not to launch.

The app runs, the UI looks great, and five problems sit underneath. You can't see them from the browser. Attackers can.

🔓

Open database

RLS off or using (true). Anyone with your public anon key can read every row.

🔑

Leaked keys

Service-role and Stripe keys in the repo or behind a NEXT_PUBLIC_ prefix.

💸

Free "Pro"

Customers who cancel and keep Pro because subscription.deleted is never handled. Unsigned webhooks, prices sent from the browser.

🚪

Fake auth

Admin checks in useEffect. The UI hides the data, but the API still serves it.

🧯

No launch basics

Ignored build errors, no rollback, no monitoring, auth emails landing in spam.

⚠It already happened at scale. In 2025 a researcher scanned 1,645 apps showcased by one AI app builder and found 170 (about 10%) with database rules that let anyone read or write user data. It became CVE-2025-48757. At the time, the builder's own scanner only checked that a policy existed, not that it was correct. Its built-in scans are much better now, but they read code. Ship-Ready walks your agent through a two-account test on the running app (the Crew automates it in CI). It's still happening in 2026: securityscanner.dev found RLS-off tables with real user data in about 7% of the Lovable and Bolt apps it scanned (Q2 2026), and Reeve found 2,096 of 3,680 reachable Supabase-backed apps (57%) answering a logged-out table read (Aug 2026).

FAQ

Questions

I don't know what RLS is. Is this for me?

Yes. Built for people who shipped with Lovable, Bolt, v0 or Cursor and want to know it's safe. Harbor explains every finding in plain English, says why it matters and gives the exact fix. You make the final calls.

Is this really a problem?

Outside scans keep finding about 7% of Lovable and Bolt apps with tables anyone could read (securityscanner.dev, Q2 2026). In a separate sweep, Reeve found 57% of reachable Supabase-backed apps answering a logged-out table read (Aug 2026). Those scans only see what a logged-out visitor sees. Ship-Ready walks your agent through a two-user check: can a second logged-in user read the first user's data?

Which tools does it work with?

Claude Code installs it in one line as a plugin. The same skills work in Cursor, Codex and other AGENTS.md agents, and as uploadable skills in Claude.ai. ChatGPT, Claude Projects and Gemini get paste-in system prompts.

Which stacks?

Best coverage: Next.js or Vite + Supabase + Stripe on Vercel or Netlify, which is what most AI builders generate. Firebase, Clerk, Auth.js and other hosts are covered in the playbooks with less scanner support.

Is it safe to install?

Yes, and you can check. The packs are plain Markdown skills plus one offline Python scanner you can read. There is no npm package and no install script, so nothing runs when you add it. Worth asking of any skills pack: on 22 Oct GitHub flagged npm versions of two popular skills collections as malware.

Will it change my code without asking?

No. The crew works in your local repo and proposes minimal diffs. Two human gates are built in. Rotating keys, changing dashboards, applying production migrations and deploying are always your call.

Is this a penetration test?

No. It's static analysis plus guided reviews by agents that follow senior-engineer playbooks. It catches the mistakes AI builders make most often. For regulated data, pair it with a professional pentest.

How is this different from a checklist or prompt pack?

A checklist tells you what to look for. The Crew does the looking: a deterministic scanner with file:line evidence, a lead agent that routes work to specialists, a score you can track, and a full worked audit so you can see exactly what you'll get.

I already ran a code scanner. Do I still need this?

Probably, for one reason: a code scanner reads your files, so it can say a table looks unprotected, but it can't prove your rules work on the live app. Ship-Ready also runs the two-account test: a second logged-in user tries to read the first user's rows. Lite walks your agent through it for free, and the Crew runs it automatically in CI. Run both; they catch different things.

Refunds?

If the Crew doesn't find anything worth fixing in your app, email us within 14 days for a refund.

Why isn't my score 0 when I have lots of findings?

Each type of issue costs points once, at its worst severity, so one pattern repeated 70 times does not bury everything else. The report still lists every occurrence. Fix the pattern and they all go away together.
