The bundled ship-ready-quick-scan skill runs one standard-library Python script over your app folder: committed secrets, .env not git-ignored, secrets behind NEXT_PUBLIC_/VITE_, Supabase tables with RLS off (or switched off later), using (true) read policies, views that skip RLS, API routes and Supabase Edge Functions with no caller check (verify_jwt = false), unsigned Stripe webhooks. Questions

Lovable already scans my app for free. Why use Ship-Ready?

Keep Lovable's scan on. It's a good first pass. Per Lovable's docs, its built-in scans do static analysis: they read your code and configuration.

Lite adds a second pass on your repo that runs locally, no code upload, and walks your agent through a two-account test: sign in as a second user and try to read, edit or delete the first user's rows, so you can see what the live app actually allows, not only what the config suggests. The same skills work on Bolt, Cursor, v0 or hand-written apps.
